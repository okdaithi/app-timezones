BUILD NOTES

Glance and time zones: what has to happen

A Glance widget is Compose syntax over RemoteViews. It does not run continuously. Every visible change needs either a view the launcher animates itself, or an explicit update your app triggers.

01

Zones, not offsets

Store Australia/Perth and Europe/Dublin. Perth has no daylight saving. Ireland switches between IST (UTC+1) and GMT (UTC+0), so the gap is 7 h from late March to late October and 8 h the rest of the year. A hard-coded −7 is wrong about five months a year.

02

The system ticks the clocks

Recomposing every minute is unreliable and drains battery. Embed a TextClock through AndroidRemoteViews, with android:timeZone set. The launcher redraws it every minute, and your app never wakes.

03

Recompute only at edges

The band and status change only when a window opens or closes, Ireland changes its clocks, the device's zone changes, or someone sets the clock. Schedule the next of these instead of polling.

What updates what

Window edge: 15:00 / 21:00 Perth (16:00 in Irish winter)
Irish clock change: last Sunday of March and of October, 01:00 UTC
TIMEZONE_CHANGED: you landed in the other city
TIME_SET, BOOT_COMPLETED
updateAll(context)
then schedules the next edge
provideGlance → callWindow(now)
Band, status and date labels recomposed
TextClock × 2 Separate lane: the minute digits tick in the launcher process. No broadcast, alarm or recomposition involved.

1 · The window

Both cities must be between 08:00 and 21:00. Shift Galway's hours onto Perth's clock by the live gap, then intersect. Derive the gap from ZoneRules for the instant, never from a constant.

val PERTH: ZoneId = ZoneId.of("Australia/Perth")
val GALWAY: ZoneId = ZoneId.of("Europe/Dublin")

/** Callable minutes-of-day on Perth's clock; null if the cities never overlap. */
fun callWindow(at: Instant, openHour: Int = 8, closeHour: Int = 21): IntRange? {
    val gap = (PERTH.rules.getOffset(at).totalSeconds -
               GALWAY.rules.getOffset(at).totalSeconds) / 60   // 420 (IST) or 480 (GMT)
    val start = maxOf(openHour * 60, openHour * 60 + gap)
    val end = minOf(closeHour * 60, closeHour * 60 + gap)
    return if (start < end) start until end else null
}
// IST: 900 until 1260  →  15:00–21:00 Perth = 08:00–14:00 Galway
// GMT: 960 until 1260  →  16:00–21:00 Perth = 08:00–13:00 Galway

2 · The widget

Responsive sizes map to the three layouts on the sizes board. Read Instant.now() inside the composition so every update recomputes from scratch. Never read ZoneId.systemDefault(): it changes when you fly.

class DualClockWidget : GlanceAppWidget() {

    companion object {
        val SMALL = DpSize(110.dp, 110.dp)
        val WIDE = DpSize(250.dp, 60.dp)
        val MEDIUM = DpSize(250.dp, 110.dp)
    }

    override val sizeMode = SizeMode.Responsive(setOf(SMALL, WIDE, MEDIUM))

    override suspend fun provideGlance(context: Context, id: GlanceId) {
        provideContent {
            val now = Instant.now()
            val window = callWindow(now)
            when (LocalSize.current) {
                SMALL -> SmallLayout(now, window)
                WIDE -> WideLayout(now, window)
                else -> MediumLayout(now, window)
            }
        }
    }
}

@Composable
fun ZoneClock(@LayoutRes layout: Int) {
    val context = LocalContext.current
    AndroidRemoteViews(RemoteViews(context.packageName, layout))
}

class DualClockReceiver : GlanceAppWidgetReceiver() {
    override val glanceAppWidget: GlanceAppWidget = DualClockWidget()
}

3 · Ticking digits

One layout per zone. TextClock resolves the IANA zone itself, including Ireland's clock changes. clock_galway.xml is identical with Europe/Dublin.

<!-- res/layout/clock_perth.xml -->
<TextClock xmlns:android="http://schemas.android.com/apk/res/android"
    android:id="@+id/clock_perth"
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:format24Hour="HH:mm"
    android:format12Hour="h:mm"
    android:timeZone="Australia/Perth"
    android:fontFamily="monospace"
    android:textSize="38sp" />

4 · Scheduling the next edge

One receiver handles the alarm and the system broadcasts. TIMEZONE_CHANGED and TIME_SET are exempt from Android 8's implicit-broadcast limits, so the manifest can declare them. An inexact alarm is enough. A band that flips a minute late is invisible, and exact alarms need the SCHEDULE_EXACT_ALARM permission.

class BandRefresh : BroadcastReceiver() {
    override fun onReceive(context: Context, intent: Intent) {
        val pending = goAsync()
        CoroutineScope(Dispatchers.Default).launch {
            try {
                DualClockWidget().updateAll(context)
                scheduleNext(context)
            } finally {
                pending.finish()
            }
        }
    }
}

fun scheduleNext(context: Context) {
    val now = Instant.now()
    val next = listOfNotNull(
        nextWindowEdge(now),                         // next start or end of callWindow, as an Instant
        GALWAY.rules.nextTransition(now)?.instant    // Perth has none
    ).min()
    val pi = PendingIntent.getBroadcast(
        context, 0, Intent(context, BandRefresh::class.java),
        PendingIntent.FLAG_IMMUTABLE or PendingIntent.FLAG_UPDATE_CURRENT
    )
    context.getSystemService(AlarmManager::class.java)
        .setWindow(AlarmManager.RTC, next.toEpochMilli(), 60_000L, pi)
}

<!-- AndroidManifest.xml -->
<uses-permission android:name="android.permission.RECEIVE_BOOT_COMPLETED" />
<receiver android:name=".BandRefresh" android:exported="true">
    <intent-filter>
        <action android:name="android.intent.action.TIMEZONE_CHANGED" />
        <action android:name="android.intent.action.TIME_SET" />
        <action android:name="android.intent.action.BOOT_COMPLETED" />
    </intent-filter>
</receiver>

Pitfalls

The device zone is not a widget zone. A person who lives in both cities changes systemDefault() twice a trip. The widget reads only its two fixed ZoneIds. The broadcast only triggers a refresh.
Dates are per zone. Before about 07:00–08:00 Perth time, Galway is still on the previous day. Format each date with its own zone. Never subtract hours from a Perth LocalDate.
Alarms die on reboot. Reschedule on BOOT_COMPLETED and in the receiver's onUpdate. Otherwise the band freezes until the next zone or time broadcast.
Rules change. tzdata ships with OS updates. Compute from ZoneRules at each update and never persist an offset. The window then stays correct if Ireland ever changes its daylight-saving policy.
